## Важные детали по задачам

**TKT-002 — сначала Redis, потом БД (не наоборот):**
1. Атомарно списать места в Redis (Lua script)
2. Только если Redis дал добро — создать Ticket в БД
3. Если "оплата" упала — вернуть места в Redis + удалить Ticket

**EVT-006 — не забыть инициализировать Redis seats:**
При publish: `await redis.set(f"event:seats:{event.id}", event.capacity)`
Это единственное место где seats попадают в Redis. Пропустишь — TKT-002 сломан.

**SRCH-001 — динамический запрос, не отдельные функции:**
Один запрос с динамическими `.where()` для каждого фильтра.
Не делать отдельный метод репозитория для каждой комбинации фильтров.

**NOTIF-002 — email должен реально доходить:**
Проверить на реальном ящике (Gmail / Mailtrap).
QR-код прикрепить как вложение: сгенерировать PNG в памяти, передать в письмо.
